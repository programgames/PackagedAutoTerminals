# 诊断

## Machines 标签

Machines 标签一打开就是报告。报告列出已编码配方中，ME 网络里没有任何合成器能执行的每一种配方类型。
没有其他模组会报告这些配方。

报告的每一行都是橙色，因为它表达的是一个疑问，而不是一个故障。终端只能看到 ME 网络。ME 网络之外的
合成器仍可能执行该类型，例如放在解包机旁边，或位于 Package Crafting Machine Proxy 后面。该行的提示
会说明这一点。

报告下方是两节内容。Crafters 一节列出网络中的封包合成器。Routers 一节列出只负责搬运封包的机器，即
Positioned Package Distributor 和 Package Crafting Machine Proxy。

对每一台机器，该标签给出其名称和状态：

| 状态 | 含义 |
|---|---|
| 未激活，红色 | 该机器没有频道。它什么都不执行。 |
| 忙碌 | 该机器正在合成，或者持有待合成的物品。 |
| 无配方，红色 | 没有任何已编码配方指向这种机器。 |
| 配方数量 | 这种机器能执行的已编码配方数量。 |

## 为什么这份报告重要

PackagedAuto 失败时不出声。设想一个为 Elite 工作台编码的配方，放在只有 Basic 工作台的网络里。该
配方永远不会运行。没有变红。日志里也没有记录。物品不会到。这个错误在游戏里很常见。

## 读懂报告

当某个配方类型指向 ME 网络中不存在的合成机器时，该标签就会报告这个类型。

我们为每个集成各写一张表。这张表把配方类型映射到合成器类。需要这张表，是因为
`IRecipeType.getRepresentation()` 返回的是合成的来源工作站，而不是封包合成器。如果某个配方类型
不在表里，该标签就不会报告它。它不会猜测。

## 找到一台机器

图钉按钮在 Patterns 标签上，不在 Machines 标签上。

1. 打开 Patterns 标签。
2. 点击某一行分组上的图钉按钮。

终端会在世界中标出该分组的所有机器。它画出一个染色方块和一道向上的光柱。标记持续十五秒，时长由
配置项 `highlightSeconds` 决定。
