# 疑难解答

## 各种拒绝信息的含义

| 信息 | 含义 |
|---|---|
| 先向该机器放入一个样板包储存器 | 该机器没有储存器，并且服务器把 `pullHolderFromNetwork` 设为 `false`。在这个设置下，终端绝不会自行从仓储中取出储存器。这由你决定。 |
| 网络中没有空白的样板包储存器 | 该机器没有储存器。`pullHolderFromNetwork` 为默认值 `true`，所以保存时终端会从 ME 网络中取出一个空白储存器。网络中一个也没有。 |
| 你没有在该网络上建造的权限 | 该网络的 AE2 安全设置拒绝给你 Build 权限。没有这个权限，终端不会打开。 |
| 再次点击以删除此配方。 | 第一次左键点击配方行上的叉号只是提醒你。三秒内在同一个配方上再点击一次，才会删除它。 |
| 再次 Shift+左键点击以将储存器发送到网络。 | 第一次在分组行上 Shift+左键点击只是提醒你。三秒内在同一行上再点击一次，才会把该分组的储存器连同其配方送回网络。 |
| 该分组已满：最多 20 个配方 | 该分组已达到配方数量上限。这个上限属于样板包编码器，不属于本模组。 |
| 该分组已变化：请重新打开配方 | 你打开的那个配方已经不在分组里了。另一名玩家，或者对某台机器的改动，把它移走了。 |
| 这个比例无法整除每个格子 | Keep ratio 拒绝了这次修改，并且什么都没改。不会有配方停在改到一半的状态。 |
| 这个比例会让某个格子超过 %d | Keep ratio 拒绝了这次修改，因为有一个格子会超过它自身的上限。 |
| 合成配方每格只消耗一个物品 | PackagedAuto 在合成配方上把数量强制为一。 |
| 未保存配方。再次点击以放弃修改。 | 第一次点击提醒你。第二次点击才离开该配方。你不会在没有提示的情况下丢失内容。 |
| 已应用至 2 个机器，1 个机器没有储存器 | 终端写入了配方，但分组中有一台机器没有样板包储存器。终端没有为它取出储存器，因为 `pullHolderFromNetwork` 为 `false`，或者网络中没有空白储存器。 |
| 已应用至 2 个机器，从网络取用储存器 1 个 | 这不是拒绝。终端写入了配方，并为一台没有储存器的机器从 ME 网络中取出了一个空白储存器。把 `pullHolderFromNetwork` 设为 `false`，储存器就只由你亲手放入。 |
| 未写入任何内容 | 分组中没有任何机器接受该配方。 |

## 终端自己关闭了

你离开范围或无线终端电力耗尽时，无线终端会关闭。有线终端在失去网络时关闭。你失去该网络的 Build
权限时，两种终端都会关闭。编辑器遵循同样的规则。它会关闭。它不会显示一个它已经无法写入的配方。

## 界面放不进你的窗口

两个界面在打开期间会调低游戏的 GUI 缩放。关闭时它们把原值还回去。它们只在内存中改动这个值，绝不会
改写你的选项文件。

终端高 331 像素，显示十行，所以 1920 乘 1080 的窗口能保持 GUI 缩放 3。编辑器高 338 像素。
Minecraft 只保证 320 乘 240 像素的窗口。

## 两台机器本该属于一个分组

终端会把携带完全相同配方的两台机器合并。共用一个配方并不够。

如果一个分组裂成两组，说明其中一侧少了一个配方。请给两侧取同一个名称：

1. 左键点击其中一行。编辑器打开。
2. 在编辑器顶部的名称框里输入一个名称。
3. 对另一行做同样的操作，用同一个名称。

终端随后按名称把两行合并，无论它们的配方为何。下一次保存会写到分组中的所有机器。

## 某个配方永远不运行

打开 Machines 标签。如果该配方的类型以橙色出现在标签顶部的报告里，说明 ME 网络中没有能执行该类型
的合成器。ME 网络之外的合成器仍可能执行它，例如放在解包机旁边，或位于 Package Crafting Machine
Proxy 后面。关于这份报告，请阅读[诊断](Diagnostics-zh)。

## 反馈缺陷

1. 在仓库中提交 issue。
2. 写明 Minecraft、Forge、AE2UEL 和 PackagedAuto 的版本，以及你使用的附属模组。
3. 写明可复现问题的步骤。
4. 附上一张界面截图。
